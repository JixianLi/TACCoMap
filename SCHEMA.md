# TACCoMap data contract

Pipeline: `harvest/<source>.py` → `data/normalized/<source>.json` → `harvest/build.py` → `web/data/*.json` → static browser in `web/`.

Raw API responses are cached in `data/raw/<source>/` (gitignored). Every record carries `sources[]` provenance.
Maintainer-only build outputs go to `data/review/` (gitignored, never published; see Review files).

## Normalized file (`data/normalized/<source>.json`)

```json
{ "source": "openalex", "retrieved_at": "ISO-8601", "query_description": "human-readable query used",
  "collaborations": [], "people": [], "institutions": [] }
```

## Collaboration

| field | notes |
|---|---|
| `id` | `paper:doi:<lowercased doi>` (fallback `paper:openalex:W…`), `award:<funder>:<award number>`, `subaward:usaspending:<prime award id>:<sub-award id>:<action date>:<amount>` (one per FFATA report; rows identical in all four parts get an ordinal suffix `:2`, `:3`, …), `dataset:doi:<doi>`, `allocation:access:<request number>`, `opportunity:grantsgov:<id>` |
| `kind` | `paper` \| `award` \| `subaward` \| `dataset` \| `allocation` \| `funding_opportunity` |
| `relationship_types` | list; values below. A record can have several (e.g. staff co-authored AND acknowledges TACC) |
| `title`, `year`, `start_date`, `end_date` | dates ISO `YYYY-MM-DD` or null |
| `amount_usd`, `funder`, `venue`, `url`, `description` | optional, null if unknown |
| `identifiers` | dict, e.g. `{"doi": …, "openalex": …, "award_number": …}` |
| `participants` | list of participant objects (below) |
| `participants_truncated` | true if the source truncated the author/creator list |
| `sources` | list of `{source, source_record_id, url, retrieved_at}` |

### `relationship_types` vocabulary

| value | meaning |
|---|---|
| `staff_coauthor` | paper/dataset with at least one TACC-affiliated author |
| `resource_acknowledgment` | paper whose full text mentions TACC but has no TACC-affiliated author (resource user) |
| `tacc_lead_award` | award where a TACC person is the lead PI |
| `tacc_partner_award` | award where a TACC person is co-PI, or TACC is a named sub-recipient |
| `tacc_mention_award` | award whose abstract mentions TACC, no TACC person listed |
| `subaward` | money flow between institutions under a TACC-related prime award |
| `tacc_hosted_data` | dataset published through a TACC-operated repository (e.g. DesignSafe) |
| `tacc_resource_allocation` | allocation of time on a TACC system |
| `funding_opportunity` | open/forecasted solicitation relevant to TACC-type work (not a collaboration per se) |

**Date cut (build.py).** Only collaborations dated 2001-01-01 or later are built: TACC was formally formed in 2001, and
earlier supercomputing-center records do not count. The date is `start_date` (award/allocation start, publication
date, subaward action date), else `year`. Undated records are kept. Subawards of dropped primes are dropped. The cut
runs before institution and person resolution, so dropped records are never evidence; people referenced only by
dropped records are removed. build.py prints the dropped count per kind and the number of undated records kept.

## Participant (one party in one collaboration)

Institution is recorded **as of that collaboration**, never as a person's current location.

| field | notes |
|---|---|
| `person_id` | id of a person record, or null for organization-only participants. In the published `web/data` it is null unless the person is a direct collaborator (on a record with relationship type `staff_coauthor`, `tacc_lead_award`, `tacc_partner_award` or `tacc_resource_allocation`); only those people are in `people.json`, and `person_display_name` is likewise kept only for them. `data/review/people_full.json` keeps everyone |
| `person_display_name` | build.py, the person's `display_name`, so participant lists can show it without loading people.json; `name_as_listed` stays the name printed on the record. Left out of `web/data` when there is no person or it equals `name_as_listed` (readers fall back to `name_as_listed`) |
| `name_as_listed` | the person or organization name exactly as the source lists it |
| `role` | `author`, `pi`, `co_pi`, `creator`, `contributor`, `awardee_org`, `subawardee_org`, `prime_awardee_org` |
| `roles` | DataCite only: every role of a person listed under several roles on one record (creator + contributor are folded into one participant; `role` is `creator` if any listing is) |
| `institution_id` | `ror:<id>`, `openalex:I…`, `name:<normalized>`, or null |
| `institution_name_as_listed` | affiliation string as the source lists it, with street-level pieces removed (see Addresses and contact details); `[address removed]` for a personal address; null when the source lists none (an institution inferred from evidence is never written here) |
| `institution_status` | `resolved` \| `unresolved` (free text only) \| `missing` (source gives none, the string names no organization, or no evidence; shown as "unknown") |
| `institution_match_method` | build.py, how a free-text string was resolved or rejected: `manual_alias`, `dataset_name_exact`, `ror_affiliation_api`, `tacc_name`, `not_an_institution:<placeholder\|place_or_address\|personal_address\|collaboration_name\|record_title\|citation_fragment\|observed_non_institution>`, or `bulk_affiliation_guard` (see Bulk affiliations) |
| `additional_institution_ids` | other affiliations listed for this person on this same record (multi-affiliation authors); `institution_id` is the first listed |
| `institution_evidence` | how the institution was determined: `{method, detail, confidence}`. `method` ∈ `source_listed` (the record itself lists it), `nsf_awardee_rule` (NSF lead PI must be at the awardee), `openalex_author_affiliation_years`, `orcid_employment`, `usaspending_subaward`, `cross_award_dated` (same person's other award in an overlapping period), `ror_affiliation_api`, `manual`. `confidence` ∈ `high` \| `medium` \| `low`. `detail` always names the years or period used. When no evidence exists the institution is null and status is `missing` (shown as "unknown"). Never assume a co-PI's institution without evidence. |
| `current_email_domain_is_tacc` | NSF only, `data/normalized/nsf.json` only (dropped from `web/data`): whether the PI's *current* NSF contact email is a TACC address. A hint for reviewers, never evidence for any award (the email itself is never stored) |

**Strings that name no organization.** Unresolved affiliation strings that are placeholders (`N/A`, `Unknown Institution`, `co-PI`, `Dept. of`, single symbols, …), only a place or address (`Nagoya , Japan`, `Madison`, `Staudinger Weg 7`; places come from the city/state/country names of ROR records in the dataset), only collaboration names (`for the IceCube Collaboration`; also when OpenAlex had resolved such a string), the record's own title, a `PoS(` citation fragment, or one of a few hand-checked strings become `missing`: `institution_id` and `institution_evidence` null, the raw string kept in `institution_name_as_listed`, `institution_match_method` = `not_an_institution:<kind>`. Extra `name:` affiliation ids of the same kinds are removed from `additional_institution_ids`.

**Addresses and contact details.**
- *Personal address* (`not_an_institution:personal_address`): an unresolved string (or a `name:` additional id) that is a private site (residence, GPS coordinates), or contains a street, PO box / Caixa Postal, flat number, full postcode or an "unaffiliated" / "independent" / "retired" marker while no part of it names an organization. `institution_name_as_listed` becomes `[address removed]`, no `name:` institution is created, and the build log prints counts only. An organization-only participant named by the same string (DesignSafe sensor sites) also gets `name_as_listed` = `[address removed]`.
- *Street stripping*: after ROR matching (so matching and its cache see the full string), house number and street, number-after-street (European forms), PO box, private bag and suite pieces are removed from every `institution_name_as_listed`, and `name:` ids built from those strings are rebuilt to match. City and postcode stay.
- *Contact details*: harvesters pass names, affiliations, titles and descriptions through `common.scrub_contact_details`, which replaces labelled contact values, mailto links, plain and obfuscated emails, personal social-media profiles (Twitter/X, Facebook, Instagram, LinkedIn `/in/`), GitHub profile pages (not repositories), `*.github.io` pages and phone numbers with `[contact removed]`. In affiliation strings and author names the marker is dropped instead, because those strings become `name:` ids.
- *Descriptions*: NSF, NIH, USAspending and ACCESS descriptions are cut to 400 characters; Grants.gov synopses to 4,000.

**Bulk affiliations.** On papers with ≥50 participants, an institution held (primary or additional) by more than half of the participants is removed from all of them; when the author list is truncated (`participants_truncated`, OpenAlex `is_authors_truncated`, which keeps only the first 100 authors; true if any merged source says so) the threshold is more than one third. Both comparisons are strict and use exact fractions. OpenAlex smears collaboration member institutions over whole author lists (IceCube ICRC proceedings: Southern University, Clark Atlanta, UT Arlington, Alaska Anchorage, LBNL, …). A removed primary becomes `missing` (`institution_id`/`institution_evidence` null, raw string kept in `institution_name_as_listed`, `institution_match_method` = `bulk_affiliation_guard`); a removed additional id is dropped. Other additional ids are not promoted to primary, so such a participant may be `missing` with non-empty `additional_institution_ids`. The browser shows the removed string greyed out with a note and leaves it out of search. Runs after name resolution and before ORCID plausibility, award assignment and person resolution. Precision over recall: genuine links of real members on guarded papers are lost too (e.g. Southern University's own IceCube member). Known false positive: SPHEREx (`10.1117/12.2567224`, Caltech genuinely the majority, but its affiliations are also scrambled by author position). The one-third rule removes 1,049 links on 13 truncated papers (ICEHAP Chiba 40–48% on 11 IceCube lists, Pierre Auger 49/99, a 15-institution union at 34–37% on the FACT/H.E.S.S./MAGIC/VERITAS paper); it also removes a few genuine links inside a smeared institution (2 real Chiba authors on 1.444.1037, e.g. LLR on 1.444.1501). Known misses: smears below the threshold (Chiba at 24–27% on 3 truncated IceCube papers, ~77 links; lowering the threshold would also hit the legitimate CNRS 33/99 on `10.3847/1538-4357/ac6def`) and smaller leftovers (~25 Southern University links on IceCube papers). The local diagnostics file at `BULK_AFFILIATION_PAPERS_PATH` (`harvest/build_institutions.py`, outside the repo) records `participants_truncated` and `min_share` per paper and `share_band` per removed institution; build.py prints counts per band.

**TACC strings.** A string naming TACC ("Texas Adv(anced) Comput(ing/er) Cent(er/re)", or "TACC" together with Texas, Austin or UT) resolves to TACC (`ror:00xg4bh43`, method `tacc_name`) whenever it would otherwise be UT Austin or unresolved, including participants the source itself had resolved to UT Austin. Strings whose primary institution is another organization are left alone.

**Institution at the time (awards).** One evidence rule for lead PIs and co-PIs. A person's institution must be supported by the person's own dated affiliations overlapping the award's **active period** [start year, end/expiration year] (start year only if there is no end date): ORCID employment spans and OpenAlex years with works, from `data/evidence/affiliation_evidence.json` (high/medium person matches only). Co-PIs added after the award started are part of the collaboration and use the same period. If the person has no dated evidence inside the period at all, the year before the start (the proposal year) is used, and the detail says so. ORCID alone decides when its spans cover every year of the period up to the current year; otherwise ORCID and OpenAlex are pooled. A person's *current* email or affiliation is never evidence for a past award.
- **ORCID plausibility first.** build.py runs the person ORCID plausibility check (see Person) before award assignment. An evidence ORCID rejected for that person contributes no ORCID employment; the OpenAlex years of the same entry still count. An evidence link named by a `strip_orcid` entry in `person_aliases.json` drops the whole evidence entry (ORCID and OpenAlex), because the matched profile is the same wrong identity.
- **Nesting.** Nested affiliations collapse to the most specific (UT Austin + TACC → TACC). An organization with more than one ROR parent (a consortium such as NSF CI Compass) is never treated as a unit of any parent.
- **TACC vs UT Austin.** OpenAlex TACC evidence counts only if TACC years are at least half of the years at an institution containing TACC (UT Austin), or if ORCID lists TACC employment. Weaker TACC evidence counts as UT Austin.
- **Lead PI.** Keeps the awardee (`nsf_awardee_rule`), refined to TACC when evidence in the period passes the TACC test.
- **Co-PI.** Exactly one candidate → assigned. Several → the unique one that is (part of) the awardee or a USAspending subawardee under that prime, **only if** the person's evidence covers it (with its nested units) in at least as many years of the period as every other candidate; confidence at most `medium`, detail lists the tied institutions. A subawardee is only ever chosen from the person's own evidence (`usaspending_subaward`). Otherwise unknown (logged as a conflict with its `window`).
- **Cross-award.** A co-PI still unknown whose own evidence did not conflict takes the same person's resolved institution on another NSF/NIH award (awardee rule or dated evidence; never another cross-award result) when the active periods overlap within ±1 year and exactly one institution remains after nesting collapse (`cross_award_dated`, `medium`). Same person = same person id, or identical normalized full name including a middle name/initial. More than one institution → unknown.
- **Consistency.** Someone placed at UT Austin on one award and at TACC on another award whose period strictly overlaps is refined to TACC (`cross_award_dated`).
- **Inferred, not listed.** A placement from dated evidence (`orcid_employment`, `openalex_author_affiliation_years`, `usaspending_subaward`, `cross_award_dated`) sets `institution_id`, `institution_status` and `institution_evidence` only; `institution_name_as_listed` keeps what the source listed (null for NSF co-PIs; the awardee name for a lead PI refined to TACC). ORCID employment years quoted in `institution_evidence.detail` are clipped to the award period. The browser marks these rows "inferred" with the method, and shows the evidence detail on hover.
- `relationship_types` for NSF/NIH awards is then recomputed: `tacc_lead_award` if the lead PI was at TACC, `tacc_partner_award` if a co-PI was or the abstract names TACC as a partner, else `tacc_mention_award`.

## Person

`id` priority: `orcid:<0000-…>` > `openalex:A…` > `nsf:<piId>` > `nih:<profile_id>` > `name:<normalized name>|<source>`.
Fields: `name`, `orcid`, `openalex_author_id`, `other_ids` (dict), `sources`. Merged people also carry `display_name` (below).

**Person resolution (build.py).** Precision over recall: a merge or an ORCID assignment happens only on unambiguous evidence; anything ambiguous stays separate and is listed in the merge log for maintainer review.

**Hard evidence (round 5).** An ORCID stays on a record whose name alone is not enough, and a merge that needs the nickname table happens, only on hard evidence; otherwise the ORCID is stripped or the records stay separate, listed in the merge log for maintainer review. Hard evidence for an ORCID on a record is: the ORCID's public works list the record's DOI (works overlap); the source itself asserts the ORCID for that author (DataCite creator/contributor `nameIdentifier`, entered by the depositor; OpenAlex authorship ORCIDs come from OpenAlex's author clustering and do not count; Crossref is not harvested); an ORCID employment/affiliation matching the institution listed on the record in that year (±1), or, for an award PI/co-PI, the awardee or a USAspending subawardee during the award's active period (matched by ROR id with ancestors/descendants, or by name through `institution_aliases.json` and dataset ROR names; institutions taken from ORCID employment never count, as that would be circular); or the ORCID's registered name or other names containing the listed variant.
- **ORCID plausibility (step 0, before award assignment).** Uses `data/evidence/orcid_names.json` (below). Every ORCID in the dataset is name-checked (person records, participations, evidence links).
  - An ORCID stays on a record only if the listed name fits the ORCID's registered name. Family name: accent-folded, hyphens joined or split, umlaut spellings, any part of a compound surname, word order free, or a one-letter typo for surnames of 6+ letters when the given name is spelled out. Given name: initial, equal, nickname, or written together. A same-letter short form of a full name (Chris/Christopher, Joe/Joseph, Steve/Stephen, Kate/Katarzyna; the shorter name under 6 letters) counts like an initial match; a pair starting with different letters (Bill/William, Slava/Viacheslav, Juanan/Juan Antonio) or two full names in one nickname group (Stephen/Steven, Alexander/Alexandra, Philip/Phillip) needs hard evidence (below), for ORCIDs and merges alike. Greek capitals that look like Latin letters count as Latin ("Τ. S. Example"). Words written wholly in Cyrillic or Greek are transliterated (simplified BGN/PCGN, ELOT 743); Cyrillic "е"/"ё" is compared both as BGN/PCGN "ye" at the start of a word and after a vowel ("Obraztsayeva") and as plain "e" ("Elena", "Primeroev"), since scholarly romanization and most ORCID registrations use "e". "Doe, JA" / "Smith, JR" read as initials unless the whole name is in capitals. Otherwise the reason is `orcid_name_mismatch`.
  - **First-initial check.** Even when the family name fits, the ORCID is stripped (`orcid_initial_conflict`) when none of the listed given-name initials (or nicknames) matches any registered given name, credit name or other-name word ("J. Doe" vs registered "Mary Doe"). Middle names count on both sides ("R. Quinn Sample" fits "Quinn Sample"), but a person registered under a first name who publishes under the middle name ("Lee Example" vs registered "Andrew Example"), a name change, or a romanized vs English given name fails it; such cases need works overlap or a `confirm_orcid` entry. A registration with a single given name and nothing else ("John") says nothing about the family name: a listed name whose initial conflicts is stripped (`orcid_initial_conflict`), every other record needs hard evidence (`orcid_given_name_only`), and if the registered name is unavailable or given-name-only and the group's surnames conflict, all records are stripped (`orcid_name_unavailable_and_surname_conflict`).
  - **Names that need hard evidence.** A name that fits only through the nickname table (`orcid_nickname_only`, "Kate" for registered "Katarzyna"), a given-name-only registration (`orcid_given_name_only`), a name or initial conflict, and an ORCID that only ever appears under initials-only names ("P. Doe") on large-collaboration papers (≥50 authors or a truncated list; `orcid_initials_only_large_collaboration`) keep the ORCID only on hard evidence (above) or a `confirm_orcid` entry. A full name mismatch is overcome only by works overlap.
  - **Experience match.** Only for nickname-only and given-name-only names: the record shares a place (same institution or one inside the other) within 2 years with a record of the same ORCID that needed no evidence or has its own.
  - **Same variant.** A listed name kept by hard evidence or a confirmation on one record is kept on all of the ORCID's records with that name in either word order ("Ejemplo, Juanan" = "Juanan Ejemplo"). This includes initials-only names on other large-collaboration papers (e.g. an initials-only name on one experiment's papers kept by works overlap on another experiment's complete author list); whether that should count is an open decision.
  - **Works overlap.** A participation needing hard evidence keeps the ORCID by works overlap when all hold: the listed name contains the registered family name; the ORCID's public works list the record's DOI; the author list is complete (not `participants_truncated`); and no other author on the record has that family name. A person record is kept when its own name equals the listed name of one of its rescued participations. Kept records are listed in `orcid_check_overrides`.
  - The nickname table used here also feeds name-based merging (below), where a nickname-only match needs secondary evidence.
  - For ORCIDs whose public activities were fetched (TACC staff, award PIs/co-PIs, allocation PIs and evidence-linked ORCIDs only), at least one record must be corroborated by a DOI in the ORCID's works, DataCite metadata listing the ORCID, or an ORCID affiliation matching the record's institution in that year (±1) or the award's awardee/subawardee during its active period (same matching as hard evidence). Institutions taken from ORCID employment do not count (circular). Award co-PI institutions are not yet assigned when this runs, so they do not count either. If nothing corroborates: `orcid_public_record_unrelated`. An empty ORCID record is stripped only if another ORCID in the dataset has a compatible name (`orcid_public_record_empty`). DataCite corroboration applies only to this activities check: the name check runs first and can strip an ORCID that DataCite asserts for that creator.
  - **Confirmed ORCIDs.** Records covered by a `confirm_orcid` entry in `person_aliases.json` (below) are never stripped by any automatic check (name, initial, unrelated, empty). Manual `strip_orcid` entries still apply first.
  - Stripped participations move to the record's own OpenAlex cluster (`openalex:<id>`) when the listed name fits that cluster's name, else to `name:<normalized>|<source>`. A record whose own display name mismatches keeps the ORCID for the participations that fit, gets a fitting display name, and loses its OpenAlex author id. A record stripped by a manual `strip_orcid` entry is shown under its most common listed name.
  - Full person records (`data/review/people_full.json` only; never in `web/data/people.json`) carry `orcid_rejected: [{orcid, reason, registered_name}]` and sometimes `orcid_rejected_openalex_author_ids`, and `orcid_check_overrides: [{orcid, name_as_listed, reason}]` for records kept despite failing a check (reason starts with `works_overlap:`, `source_asserted:`, `orcid_affiliation:`, `experience_match:`, `same_variant:` or `confirmed_by_maintainer:`).
  - **After merging.** A merged group with one ORCID loses it when a member record was itself rejected for that ORCID (`orcid_rejected_by_merged_record`), or a merged full name fails the full-name or first-initial check without hard evidence (`<failure>_after_merging`, e.g. "Jordan F Sample" vs registered "Julia Sample"). The group stays merged.
  - **Order limit.** The ORCID check runs before merging: a full-name record that joins later ("Katarzyna Sample" from NSF) does not restore an ORCID already stripped from nickname records ("Kate Sample"). Rejected evidence links are not hard keys, and their ORCID employment spans are not used for name merging or award institutions.
- **Hard keys:** ORCID, OpenAlex author id, NSF piId, NIH profile id, plus the ORCID/OpenAlex ids the evidence file links to NSF/NIH people (refused when middle initials differ). Records sharing any hard key merge; two different ORCIDs never merge. Merges are logged as `hard_key:<type>` (including records build.py folded by identical id across sources, with a `merged_source` field) or `affiliation_evidence_<orcid|openalex>`.
- **Name merging** repeats until nothing changes (at most 10 passes). A group merges into another only when every pair of names is compatible (same surname, given names equal/initial/nickname, no middle-initial conflict) AND both list the same place in an overlapping window. "Same place" = the same institution or one a ROR ancestor/descendant of the other (TACC = UT Austin), not siblings; participations count ±1 year, evidence spans as stated. Several sharing candidates are accepted only if their names are mutually compatible and at most one has an ORCID. Keyed sources (split OpenAlex profiles) and initial-only matches also require that no other ORCID group anywhere has a compatible name. Initial-only matches additionally need no competing incompatible full names anywhere (checked for either side) and fewer than 20 namesake groups. A merge relies on a nickname only when no name pair of the two groups is compatible without the nickname table ("Chris Sample" / "Christopher Sample"; "C. Sample" matches by initial and is not affected); such a merge also needs secondary evidence: a second shared place in an overlapping window that is not the same as or inside/around the first, the target ORCID's registered name or other names fitting a source name without nicknames ("Isa G. Doe" for registered "Isa Doe", "Greg Sample" for other name "Greg"), or works overlap on a source participation. The merge evidence then ends with "nickname supported by …". Refusals are logged with ids and a reason: `several_orcid_groups_share_place_and_window`, `candidates_with_conflicting_names_share_place_and_window`, `other_orcid_namesakes_elsewhere`, `initial_only_competing_full_names`, `initial_only_common_name`, `nickname_only_without_secondary_evidence`.
- **NSF name-only records** (`name:*|nsf`, no key) merge only when exactly one group has an exactly equal parsed name (full given name, same middle initials, same surname) and a dated participation or evidence span inside the award's active period at the awardee or a USAspending subawardee (`nsf_name_award_period_evidence`).
- Drop an OpenAlex author id/ORCID from an authorship when the raw listed name shares no surname with the assigned author (OpenAlex misattribution).
- **`data/manual/person_aliases.json`:** `{"merge": [{"person_ids": [id, id, …], "reason"}], "split": [{"id", "reason"}], "strip_orcid": [{"person_id" | "openalex_id", "orcid", "reason"}], "confirm_orcid": [{"orcid", "person_ids"?, "name_variants"?, "reason", "confirmed_by": "maintainer"}], "display_name": [{"person_id", "display_name", "reason"}]}`. `display_name` sets the name shown for a person (matched through `merged_ids`, so any id folded into the person works); `reason` gives the source of the preferred name. `merge` forces merges (overriding the two-different-ORCIDs rule), and its `reason` points to public evidence like every other entry; `split` blocks an id from any automatic merge; `strip_orcid` removes an ORCID from a person record (or the records carrying an OpenAlex id) and rejects the matching evidence link. Manual strips apply before the automatic checks. `confirm_orcid` is how the maintainer confirms an ORCID the automatic checks would strip: it covers the ORCID's records whose person id is in `person_ids` and/or whose listed name is in `name_variants` (all of the ORCID's records if both are omitted); `reason` points to public evidence only (a DOI, an ORCID works or employment entry, a DataCite or OpenAlex record), never personal background. Any entry that matches nothing prints a warning.
- Merged person: `id` (highest-priority key), `merged_ids` (all ids folded in), `name_variants`, `collaboration_count`, `display_name` (the name to show: a `display_name` manual entry, else `name`; e.g. "R. Quinn Sample" for registered "Robert Sample"). `name` stays the name taken from the data, kept for provenance. The browser shows `display_name` for people and searches id, `display_name`, `name`, `name_variants`, `orcid`, `openalex_author_id` and `other_ids`; participant rows in collaboration and institution views show `name_as_listed`.
- **`data/review/person_merge_log.json`** (never published): `{generated_at, merges: [{kept_id, merged_id, linked_to, reason, evidence, merged_source?}], refused_merges: [{ids, reason, refused_because, evidence?, …}], stripped_orcids: [{orcid, person_id, new_person_id, name_as_listed, reason, collaboration_count, example_collaboration_ids}]}`. Stripped ORCIDs are also listed in `refused_merges` with `refused_because: "stripped_orcid: …"`.
**Never store email addresses**, even when a source exposes them.

## Published files (`web/data/`)

`build.py` writes `meta`, `papers`, `awards`, `datasets`, `allocations`, `funding_opportunities`, `people` and `institutions` (`.json`). What is left out on purpose:
- **People** pass through an allowlist (`PUBLISHED_PERSON_FIELDS` in `harvest/build.py`): `id`, `name`, `display_name`, `orcid`, `openalex_author_id`, `other_ids`, `merged_ids`, `name_variants`, `sources`, `collaboration_ids`, `collaboration_count`. Every one is read by the browser; any field added to person records later stays unpublished until it is added there. The ORCID QA fields (`orcid_rejected`, `orcid_check_overrides`, `orcid_rejected_openalex_author_ids`) are therefore only in `data/review/people_full.json`.
- **Participants** lose `current_email_domain_is_tacc` (`UNPUBLISHED_PARTICIPANT_FIELDS`); it stays in `data/normalized/nsf.json`.
- **The person merge log** is written to `data/review/`. A `web/data/person_merge_log.json` left by an older build is deleted on every build.

## Review files (`data/review/`, gitignored, never published)

Maintainer-only outputs of `build.py` (`--review-directory DIR` writes them elsewhere):
- `person_merge_log.json`: merges, refused merges and stripped ORCIDs (format under Person).
- `people_full.json`: every person record with all fields, including the ORCID QA fields.

## Publishing guard (`harvest/check_publishable.py`)

Stdlib-only check that fails (exit 1) on anything that must stay local. Matches are reported by location and count only, never by value, so the output is safe to share.
- `python3 harvest/check_publishable.py`: tracked plus untracked-not-ignored files, plus everything under `web/`.
- `python3 harvest/check_publishable.py PATH ...`: the given files or folders, recursively.
- `python3 harvest/check_publishable.py --staged`: the index copies of staged files (what will actually be committed).
- `python3 harvest/check_publishable.py --site DIR`: a staged GitHub Pages folder; fails on any file outside the allowlist (`index.html`, `style.css`, `app.js`, `data.js`, `data/{meta,papers,awards,datasets,allocations,funding_opportunities,people,institutions}.json`) and on any allowlisted file that is missing, then runs every content check.

Checks: paths under `data/raw/`, `data/evidence/`, `data/normalized/`, `data/review/` or a publish staging folder (`publish/`, …); any `person_merge_log*.json`; files over 45,000,000 bytes; emails (plain and obfuscated), mailto links, phone numbers; personal social-media profile URLs; the ORCID QA field names as JSON keys; person-note wording in person files (`data/manual/person*.json`, `people.json`); local absolute paths (`/Users/`, `/home/`, `/private/`); and occurrences of `$OPENALEX_API_KEY` when it is set in the environment (count only). GitHub repository links are not flagged.

**Hook.** `sh scripts/install_hooks.sh` installs a pre-commit hook that runs `--staged`. It finds the hooks folder with `git rev-parse --git-path hooks`, never overwrites a pre-commit hook it did not write, and is safe to re-run. The API-key check runs only if `OPENALEX_API_KEY` is set in the committing shell (a GUI git client usually does not have it). Bypass for one commit, after reading the failures: `git commit --no-verify`.

## Evidence files (`data/evidence/`, gitignored, regenerated from cached API responses)

`affiliation_evidence.json` (`harvest/affiliation_evidence.py`): `{generated_at, description, people: [{person_id, name, openalex_author_id, additional_openalex_author_ids, orcid, match_confidence (high|medium|low|none), match_reason, affiliations: [{institution_id, institution_name, start_year, end_year, years_with_works?, source (openalex_author_affiliation_years|orcid_employment), source_url}]}]}`, one entry per NSF/NIH PI/co-PI. Awards starting before 2001 are ignored when matching. A person→OpenAlex match (and the ORCID it brings) is kept only if a matched profile has an OpenAlex affiliation during some award period (start−1 .. end+1) at the awardee, at a USAspending subawardee of that prime, or in the awardee's country (NSF awardees are US); otherwise it is dropped with "homonym guard" in `match_reason`.

`orcid_names.json` (`harvest/orcid_names.py`): `{orcid: {given_names, family_name, other_names[], retrieved_at, activities?: {public_work_count, dataset_work_dois[], affiliations: [{section, organization, ror, city, country, start_year, end_year}]}, works?: {public_work_count, dataset_work_dois[]}} | null}`. Personal details are fetched for every ORCID in the dataset; `activities` only for TACC staff, award PIs/co-PIs, allocation PIs and evidence-linked ORCIDs; `works` only for other ORCIDs with a participation that needs hard evidence (name failure, nickname-only, given-name-only, or initials-only on large collaborations) and that works overlap could keep. Which records need hard evidence depends on `build_people.py`, so rerun `orcid_names.py` before `build.py` after changing those rules (fully cached: no requests, a few seconds). Only ORCID `/personal-details`, `/activities` and `/works` are fetched (never `/person` or `/email`); `dataset_work_dois` keeps only DOIs present in the dataset; emails, handles and phone numbers typed into other names are dropped.

## Institution

`id`: `ror:<id>` when known, else `openalex:I…`, else `name:<normalized>`.
Fields: `name`, `ror`, `openalex_id`, `country_code`, `city`, `latitude`, `longitude`, `source_types` (types as the source reports them, e.g. ROR `education`), `parent_ror` (if known), `sources`.

`build.py` adds `institution_type` ∈ `government | commercial | nonprofit | educational | research | healthcare | archive | other` and `institution_type_reason` (which rule assigned it). Institutions also carry `website` (from ROR `links` or OpenAlex `homepage_url`). Rules, in priority order:

1. Manual override (`data/institution_overrides.json`: `{"<institution id>": {"institution_type": …, "note": "<evidence>"}}`, reason `manual_override`). For hand-checked corrections only; every entry's `note` states the evidence (round-3 review entries end with "(round-3 review)").
   - **Teaching-affiliate hospitals.** A hospital or health system that is only a teaching affiliate of a university (owned by a state, region, public health service, independent nonprofit or company) is `healthcare`; university-owned or university-run hospitals and health systems stay `educational`. A hospital's `.edu` website (chop.edu, chp.edu) does not make it educational. Round-4 entries end with "(round-4 teaching-affiliate rule)" or "(round-4 audit)".
   - Federal research centers run by university consortia or universities with `.edu` websites (NCAR, NOIRLab, CTIO, Rubin, SLAC) stay `educational` by decision.
2. Website domain: `.gov`, `.mil`, `.int`, `.gov.xx`, `.gob.xx`, `.gouv.xx`, `.go.xx` (go.jp, go.kr, …), `.mil.xx`, `.gc.ca`, `.govt.nz`, `.gv.at` → `government`; `.edu`, `.edu.xx`, `.ac.xx` → `educational`; `.com`, `.com.xx`, `.co.xx` (second level, e.g. `co.uk`, `co.jp`) → `commercial`. `.org`, `.net` and bare country domains give no signal.
   - **Commercial-domain conflict.** When the domain is commercial but the organization's ROR/OpenAlex type is `education`, `facility`, `government`, `nonprofit`, `healthcare` or `archive` (a .com recruiting or legacy site, e.g. the US Air Force's airforce.com), the domain is ignored and classification continues with rules 3–5; when rule 5 decides, the reason is `source_type_over_commercial_domain:<type>`. `funder` and `other` say nothing about the sector and never override a commercial domain.
   - **Name-domain hint.** A `name:` institution without a website uses a trailing "(domain)" in its name, e.g. "(umass.edu)", for this rule, with reason `name_domain_hint:<suffix>`. The hint is not stored as the website.
3. Name contains University/College (incl. Universität, Université, Universidad, …) → `educational`. Street and town words are ignored here and in rule 6 (College Station/Park/Lane/Road/Street/Avenue/Drive; University Drive/Avenue/Boulevard/Road/Street/Place/Parkway/Way/Park/Heights/City/Circle and their abbreviations).
4. University-affiliated unit: any ROR parent organization is classified `educational` → `educational` (so TACC, SDSC, NCSA, Oden, SCI, university health systems and university-co-run joint labs are educational). ROR parent links that are founder, membership or teaching-affiliation links rather than a real university parent (RTI International, CEA Paris-Saclay, RAS institutes under an `.ac.ru` division, UPMC, IU Health, the McGill University Health Centre, Copenhagen University Hospital, …) are corrected by manual overrides.
5. ROR/OpenAlex type: `education`→`educational`, `facility`→`research`, `company`→`commercial`, `government`→`government`, `nonprofit`→`nonprofit`, `healthcare`→`healthcare`, `archive`→`archive` (museums, libraries, archives); `funder`, `other` → `other`.
6. Name heuristics for name-only institutions (prefixed `name_heuristic:`): University/College/Institute of Technology/Polytechnic/School of → `educational`; Museum/Library/Archive → `archive`; Hospital/Medical Center/Clinic → `healthcare`; Foundation/Association/Society → `nonprofit`; National Laboratory → `research`; Inc/LLC/Corporation/Ltd/GmbH → `commercial`; Ministry/Agency → `government`.
7. Unknown → `other` with reason `no_type_information`.
